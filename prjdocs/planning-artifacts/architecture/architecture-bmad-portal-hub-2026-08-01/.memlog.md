- (decision) AD-006 (MVP Data Layer) [ADOPTED]: PostgreSQL relationnel + JSONB uniquement pour le MVP (Users, Roles, Leases, metadata artifacts) — pas de pgvector/vector store tant que le Copilot IA n'est pas repris. L'indexation graph-based des artifacts BMad (FR1-FR3, traceability) est un modele d'aretes/adjacence dans le meme PostgreSQL, distinct de la Knowledge Graph IA differee (PRD sec7.2). Binds: choix de persistance Backend pour le MVP. Prevents: cablage premature de pgvector/embeddings; confusion entre graphe de tracabilite d'artifacts et Knowledge Graph IA.
- (decision) AD-007 (Zero-Setup Onboarding & Space Identity) [ADOPTED]: identifiant technique = chemin remote complet (host/org/repo); affichage = nom court du repo + badge/tooltip d'organisation uniquement en cas de collision de nom court. Premiere identite non reconnue declenche creation auto de l'espace Hub; Clients suivants avec la meme identite rejoignent automatiquement — zero etape manuelle. Statut d'espace = pending / active / access_revoked; si le Backend n'a pas encore acces lecture au repo -> pending + prompt actionnable scope au provider Git (lien direct), fallback texte generique si le provider n'est pas determinable. Binds: bootstrap Client + provisioning d'espace Backend. Prevents: deux Clients divergeant sur le schema d'identite (nom court vs chemin complet) ou sur le declencheur de creation d'espace; echec silencieux sur acces repo manquant. Source: PRD sec3.1, epics.md FR7-FR9/Story 2.3-2.4.
- (decision) AD-008 (Local Repo State Reporting - flux unique, consommateurs multiples) [ADOPTED]: le Client pousse l'etat Git local (drift, actions en cours) immediatement sur evenement Git (hook), avec un tick de securite de 10s configurable en fallback, piggyback sur le canal heartbeat WebSocket existant (AD-002). Ce flux unique est la seule source alimentant a la fois l'affichage du statut contributeur ET les Risk & Quality Signals (sec3.3) — aucun chemin de reporting separe ne doit etre construit pour l'un ou l'autre consommateur. Binds: pipeline de reporting d'etat Git. Prevents: deux consommateurs (UI statut contributeur vs moteur de risk signals) derivant le drift independamment et divergeant. Source: PRD sec3.1, epics.md FR10/Story 2.5.
- (decision) AD-009 (Statut contributeur - modele a deux axes orthogonaux) [ADOPTED]: le statut contributeur porte deux signaux distincts et non un enum combine: presence (connectee/absente, derivee de la connectivite WebSocket) et sync-state (synchronise/drift/conflit/syncing-actif/claime, derive du flux Local Repo State Reporting AD-008). Les deux sont des champs separes dans le payload WebSocket et le modele de donnees Backend; toute surface affichant le statut contributeur (Dashboard, Contributor Detail, Claim Management) doit rendre les deux axes independamment, jamais les fusionner en une seule valeur. Binds: modele de donnees statut contributeur + payload temps reel. Prevents: deux surfaces choisissant des encodages enum incompatibles (ex: l'une fusionnant 'absente' dans le sync-state, l'autre la gardant separee) impossibles a reconcilier dans un payload partage. Confirme par l'utilisateur; reconcilie avec FR14/epics.md qui decrivait un enum unique a 6 valeurs — epics.md a mettre a jour separement pour refleter ce modele a deux axes.
- (constraint) Paradigme (AD-001) inchange dans sa forme mais la portee de l'Orchestration Authority (Backend) evolue: possede desormais aussi le cycle de vie des Spaces Hub (AD-007) et le flux Local Repo State (AD-008); ne possede plus de Knowledge Graph active en MVP (differee, voir AD-003/AD-004 Deferred).
